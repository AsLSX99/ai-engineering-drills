# 特训协议：循环细则、判分四层、失败诊断

> 训练模式的执行手册。核心思想：**代码从用户键盘出来，判分器说了算，复盘才算完成。**

## 一题的完整循环

```
取题 → 复述题意（纠偏）→ 起手方案（拦方向）
  → 写 starter 副本 → 跑 run.py → 读失败 meaning 自定位
  → 分层 hints（逐条 + 自证对应行）→ 全绿
  → 对照 solution 找差距 → 讲 notes → 变异体挑战 → log pass
```

## 跑判分

```bash
python <课程仓库>/scripts/practice/run.py <题id> <代码文件>
```

- 默认不传代码文件时用该题 `starter.py`（必然全挂，用来确认判分链路通）
- 代码文件放题目录外的 `solve_<题id>.py` 或副本，**不改原 `starter.py`**（改了没法二次挑战）

## 判分四层的含义（教用户按层读）

| 层 | 检查什么 | 挂在这里通常意味着 |
|---|---|---|
| **Examples** | 题面给的示例输入输出 | 根本逻辑写错 / 返回结构不对 |
| **Properties** | 数学性质（如 softmax 和为 1、注意力权重非负归一） | 公式实现有偏差（漏 scale、漏 mask、数值不稳） |
| **Edge cases** | 空输入、单元素、容量边界、dtype/shape | 边界没想，`raises` 该抛的没抛 |
| **Reference** | 与参考解在随机 fixture 上逐位一致 | 细节错位（off-by-one、覆盖顺序、精度） |

每条失败输出带三样：`expected` / `actual` / `meaning:`（这条检查在防什么错）。**先让用户读 meaning 自己猜层，你再确认。**

## 分层提示的节奏

| 轮次 | 动作 | 前提 |
|---|---|---|
| 0 | 他自己读失败信息，说出怀疑点 | 每次失败必做 |
| 1 | 给 `hints.md` Hint 1 | 轮 0 说不出所以然 |
| 2 | Hint 2 | 仍卡 |
| 3 | Hint 3、Hint 4 | 仍卡 |
| 4 | 开放 `solution.py` 第一段（核心数据结构/签名实现） | 4 条 hints 用尽 |

规则：
- 每给一条提示，先让他讲"这条对应我代码哪一行、我原来想错在哪"
- 开放 solution 后照改跑绿 → `log --result pass --hints exceeded`，**两天后强制重考**（重考时遮住 solution 重写）
- hints 用得越少，间隔重复的毕业越快（见下）

## 间隔重复排期（drill.py 自动算）

| 事件 | 下次到期 |
|---|---|
| 第 1 次 pass（hints ≤2） | +1 天 |
| 第 2 次 pass | +3 天 |
| 第 3 次 pass | +7 天 |
| 第 4 次 pass | +14 天 |
| 第 5 次 pass | +30 天 |
| 第 6 次 pass | 毕业（不再入队） |
| pass 但 hints=3-4 | 上表基础上 ×0.5（学得不牢，更快复习） |
| hints=exceeded | +2 天重考 |
| fail | +1 天 |
| 连续 2 次 fail | 降一档难度换题，原题保持到期 |

## 失败诊断表（连续失败时对照）

| 症状 | 可能病根 | 处置 |
|---|---|---|
| Examples 层就挂 | 题意没读懂 / 返回结构错 | 回去重读 `problem.md` 的 Input and output 表 |
| Properties 挂（和不为 1、值为负） | 公式抄漏一项 | 让他手算一个 3 元素小例子对一遍 |
| Edge 挂 | 边界清单没列 | 逼他先写"这题有哪 5 种坏输入"清单再改代码 |
| Reference 挂但前三层绿 | 细节顺序/精度 | 对照 solution 只看流程图级别的差异 |
| 老挂同一条 | 概念漏洞不是手生 | 回对应课重读（`meta.json` 的 `lesson` 字段），今天收工 |

## 变异体挑战（通关后的高阶关卡）

`meta.json` 的 `mutants` 列出 3-6 个故意写错的解及其 bug 描述。全绿后：
1. 逐个读 mutant 描述
2. 说出：**哪个层、哪条检查会拒收它**，以及拒收时 expected/actual 大概长什么样
3. 全部说中 → 变异体挑战通过，日志加 `--note mutants-ok`
4. 说不上 → 提醒他这条就是他的知识盲区，安排在下次会话开场口头重考

## 时间盒

- 按 `meta.json` 的 `minutes` 计时
- 超时 50% 仍未过 → 中止，`log --result fail`，下次续做（队列保留原题）
- `train-*` / `lab-*` 类题的时间盒见 `task-kinds.md`

## 会话节奏

- 开场：`drill.py status` 报连击、到期数、上次弱项
- 每题结束：记账 + 一句"这题教会你什么"
- 收尾：最多 2 题；预告明天到期的题
- 中断保护：状态全在 `drill-progress.json`，中断零损失
